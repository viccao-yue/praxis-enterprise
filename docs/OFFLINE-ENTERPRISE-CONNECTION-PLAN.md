# 离线内网企业连接：实现方案

状态：后台导出和桌面端导入已实现；交付脚本测试、桌面端构建／类型检查及自动化测试已通过。尚未验证正式 Windows / macOS 安装包和真实离线环境。

## 员工和管理员怎么用

管理员部署时指定员工实际访问的 IP 或域名。后台使用现有的自签 HTTPS，安装完成后在服务器上导出 `企业连接.praxis`。管理员通过可信渠道把文件发给员工。员工打开桌面端「连接企业」，导入文件、确认地址，然后按原方式输入账号密码。无需公网、客户自建证书体系或员工安装系统证书。

连接文件决定客户端信任哪台服务器，必须通过可信渠道分发；不能从尚未验证身份的网站下载后直接信任。第一版不新增网页下载入口。

## 后台：生成并导出文件

- 修改 `scripts/delivery-bootstrap.py`：设置 `DELIVERY_HOST` 的离线部署沿用现有 Caddy 自签证书，安装完成后生成 `config/enterprise-connection.praxis`，并打印路径。未设置明确访问地址时维持原安装行为，不猜测员工使用的地址。
- 支持仅导出，例如 `python3 scripts/delivery-bootstrap.py --export-connection --host 192.168.1.20`。复用当前 `config/tls/cert.pem`，不重启服务、不迁移数据库、不更换证书。
- 导出前验证证书当前有效，且 SAN 包含所选 IP 或域名。地址与证书不匹配时给出明确错误，不生成文件，也不静默换证书。给老客户优先沿用员工现有地址。
- 更新 `deploy/IMMEDIATE-DELIVERY.md` 和离线包现场说明，记录导出、分发和换证流程。

文件格式为带版本号的 JSON，只包含 HTTPS 地址和公开证书，不含账号密码、令牌或私钥：

```json
{
  "version": 1,
  "backendUrl": "https://192.168.1.20",
  "serverCertificatePem": "<服务器公开证书 PEM>"
}
```

## 桌面端：导入和保存

- 在 `apps/desktop/src/connection-entry.ts` 增加「导入企业连接文件」按钮，由 `workdsh-main.ts` 打开系统文件选择器。新增 `enterprise-connection-file.ts`，严格校验文件大小、版本、字段、单张 PEM 证书和 HTTPS 地址；地址不允许携带账号、路径、查询参数或片段。
- 显示规范化地址，让员工确认文件来自管理员。使用后续登录所用的同一套 TLS 校验发起一次无账号、无密码、无令牌的 HTTPS 探测；可用 `/api/auth/me` 的预期未登录响应判断是否触达后台。**确认和探测成功后才写入新配置**。取消、导入错误或后台不可达时，原来的连接配置不动。
- 将地址和证书作为一组原子保存，兼容现有 `enterprise-backend.json` 仅含 `{ backend }` 的旧格式；重启时重新校验保存的结构。证书只用于完全匹配的 origin（协议、主机名和端口）。安装包已锁定后台地址时，不允许导入文件改到另一台服务器。

## 桌面端：校验和发送请求

- 新增主进程 `enterprise-transport.ts`。只在请求命中已导入的 HTTPS origin 时才走独立的 Node `https.request` 传输。启用 TLS 校验，仅在这条连接配置信任导入证书，验证有效期和 IP／域名，并比对对端证书的 SHA-256 指纹。不得复用全局连接池或信任配置，不跟随重定向，不降级 HTTP，也不在失败时回退到默认信任。未导入证书的现有连接继续使用默认传输。
- 接到 `enterprise-auth.ts` 的 `EnterpriseLogin` 请求入口，保留现有超时、取消、状态码和 JSON 处理语义。登录、核验、退出、桌面协作和会话正文同步共用该入口；保持现有本机转发白名单、账号权限和令牌边界，不把证书信任配置或后台令牌交给插件。
- 证书到期或被替换时拒绝连接，提醒联系管理员。管理员重新导出，员工明确确认并验证后才替换。至少保留「网络不可达」「服务器身份验证失败」与「账号或密码错误」的区别。

## 兼容性和边界

- 个人模式、既有受信任 HTTPS，以及未配置 `DELIVERY_HOST` 的安装流程继续走原路径。不改 Java 业务 API 或数据库结构。
- 同一 origin 换证书不改变工作区归属。IP 改为域名、协议或端口变化时，现有客户端会将其视为另一个企业工作区；原数据不删除，也不自动迁移。
- 普通浏览器的管理控制台和独立配置的企业模型 API 不在第一版范围内；导入文件不改变浏览器或系统的证书信任。

## 验收

1. 后台脚本：新安装导出，旧安装仅导出，地址不匹配或证书过期时拒绝导出；验证仅导出不会更换证书、写数据库或重启。
2. 桌面端：正确证书可登录；错误证书、过期证书、地址不匹配、重定向均失败。对证书失败场景验证对端没有收到密码或令牌；对重定向场景验证目标地址没有收到请求。导入失败不覆盖原配置；重启后无需重新导入，同地址换证不创建新工作区。
3. 正式 Windows / macOS 安装包：在无外网、系统未安装该证书的环境下，从导入开始跑通登录、协作收发（含附件）、正文同步和退出。另用未导入文件的原有受信任 HTTPS 连接和个人模式做回归。

已做的本地原型验证：按交付脚本的方式生成自签证书，正确证书与 IP 能完成 HTTPS POST；证书不受信任、证书指纹不符或 IP 不匹配时，服务端收到的 HTTP 请求数均为 0。这不等于产品已实现或已通过安装包验收。
