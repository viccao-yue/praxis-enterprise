# 开物 Praxis 企业控制台：旧离线包一键升级到 v3.1.1

适用范围：[构建 42150375552](https://github.com/viccao-yue/praxis-enterprise/actions/runs/42150375552) 的标准 Docker Compose + PostgreSQL 一键部署。`r2` 是升级工具修订，控制台仍为 `v3.1.1`。允许只改 Caddy 的宿主机端口，例如 `8443:443`、`8080:80`；其他 Compose 定制、外部数据库或不同旧版本不要照搬。使用 Linux 服务器上的 Python 3.9+、既有 Docker 和 Docker Compose；不需要联网、重装 Docker 或下载镜像。

## 1. 校验并预检（不停服）

把升级包和 `.sha256` 校验文件一起传到客户服务器，保留足够空间存放一次完整 PostgreSQL 备份和两份控制台文件。在有 Docker 权限的终端执行：

```bash
sha256sum -c praxis-upgrade-42150375552-to-v3.1.1-r2.tgz.sha256
tar -xzf praxis-upgrade-42150375552-to-v3.1.1-r2.tgz
cd praxis-upgrade-42150375552-to-v3.1.1-r2
sudo python3 upgrade-from-42150375552.py
```

默认安装目录是 `/opt/kaiwu-praxis-admin`，默认 Compose 项目名是 `kaiwu-praxis-delivery`。现场自定义过时，先用 `docker compose ls` 核对，再在预检、执行和回退三个命令中都追加 `--install-dir /实际路径 --project 实际项目名`。预检会核对运行中的容器挂载、HTTPS 和旧库迁移记录；预检不通过时不要跳过检查。

不需要改回 `443/80`，也不要为通过预检而修改现场 Compose。脚本会核对实际端口映射，并在原 HTTPS 端口验收。

## 2. 在维护窗口一键升级

```bash
sudo python3 upgrade-from-42150375552.py --apply
```

脚本先备份旧程序、配置和 PostgreSQL，验证备份目录可读；随后在原数据库应用 `V010`，只停启控制台 `admin` 服务并验收 HTTPS 和续期路由。数据库、Caddy、安装标识、配置、证书和数据卷沿用原部署。单实例控制台在切换期间短暂不可用。看到“升级成功”后，请确认：

- 使用客户原地址和现有账号登录管理控制台，检查原有组织、成员和许可证。
- 用支持续期的新版桌面端重新登录一次，并安排测试账号验证实际续期。脚本不持有员工账号，自动验收只检查接口存在且拒绝未认证调用。
- 地址、端口和证书不变时，不用重发已导入的连接文件。现有导出命令只生成默认 HTTPS 端口的连接地址；如果使用 `8443` 等非默认端口且要首次导入，请联系交付方生成包含实际端口的连接文件，不要把 `IP:端口` 传给 `--host`。只分发 `.praxis` 文件，不分发证书私钥。

## 3. 回退

新版自动验收失败时，脚本尝试恢复旧控制台程序。需要手动回退程序或升级中断时，使用执行阶段打印的备份目录名，例如：

```bash
sudo python3 upgrade-from-42150375552.py --rollback before-实际目录名
```

程序回退保留数据库的 `V010` 可空字段和迁移记录，不回灌备份，不覆盖升级后新增的数据。数据库恢复是单独的故障恢复操作，只能由现场 DBA 在确认丢失数据范围后执行。备份目录内包含数据库、密钥和证书私钥，应限制访问，不得把它随升级包对外转发。不要运行首次安装脚本、删除原安装目录或执行 `docker compose down -v`。
